# REVIEW.md

Comprehensive review of the starter code snippet in `app/main.py`.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | Timezone-naive shift replacement and premature integer flooring before checking grace threshold. `punch_in.replace(hour=h, minute=m)` ignores IST vs UTC offset. Furthermore, `int(...)` truncates elapsed minutes before evaluating `> 10`. For a 09:30 shift, 09:40:01 has 10.0167 min elapsed, which floors to 10 and incorrectly evaluates `10 > 10` as False, returning 0. | Punch in at `09:40:01` IST for a `09:30` shift. Rule R2 requires `late_minutes = 10`, but the function returns `0`. | Converted timestamps to timezone-aware IST datetimes, tested `diff_seconds > 600` strictly, and computed `int(diff_seconds // 60)`. |
| 2 | `compute_work_hours` (lines 40–42) | Uses Python's built-in `round()`, which applies banker's rounding (round half to even) rather than round half-up as mandated by Rule R4. | An interval of 2.125 hours (7,650 seconds). Python's `round(2.125, 2)` produces `2.12`, whereas business rule R4 mandates `2.13`. | Implemented `Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 3 | `compute_overtime` (lines 44–48) | (a) Ignores Rule R3 minimum threshold (only count overtime when >= 30 min). (b) Fails on overnight shifts (`shift_end <= shift_start`) because `date_str` sets `shift_end` on the start date rather than the following calendar day. | Punch out 15 min after shift end returns `overtime_minutes = 15` instead of `0`. On overnight shift 22:00–06:00, punch out at 06:40 IST calculates overtime > 24 hours. | Handled overnight shift next-day roll-over (`att_date + timedelta(days=1)`) and added threshold condition `minutes if minutes >= 30 else 0`. |
| 4 | `create_employee` (lines 78–85) | Check-then-insert race condition. In concurrent environments, two simultaneous requests with identical `emp_code` both pass `find_one()` because no unique database index exists. Also fails to validate `shift_start != shift_end`. | Sending parallel `POST /employees` requests with identical `emp_code` results in duplicate documents instead of one 201 and one 409. Also identical shift times return 201 instead of 422. | Created a unique index on `emp_code` at startup and caught `DuplicateKeyError` to return 409. Validated `shift_start != shift_end` returning 422. |
| 5 | `create_employee` (line 82) | `created_at` set to naive `datetime.now()` and returned as an unformatted object rather than UTC BSON date in MongoDB and epoch milliseconds in API. | Schema validation failure against OpenAPI `EpochMillis`. | Truncated UTC instant to whole seconds, stored as BSON date, and converted to integer epoch milliseconds in response. |
| 6 | `list_employees` (line 93) | Off-by-one pagination bug. `skip = page * page_size`. Since `page` is 1-indexed (per R10), `page=1` calculates `skip = 20`, skipping the first 20 employees completely. | Calling `GET /employees?page=1&page_size=20` returns employees starting from index 21 instead of index 1. | Corrected pagination offset formula to `skip = (page - 1) * page_size`. |
| 7 | `list_employees` (line 94) | Total count ignores applied filters: `total = db.employees.count_documents({})` counts the entire collection. | `GET /employees?department=Engineering` where Engineering has 5 employees out of 100 total returns `total: 100` instead of `total: 5`. | Passed active query filter: `total = db.employees.count_documents(q)`. |
| 8 | `list_employees` (line 95) | Missing sort order. Documents are returned in natural MongoDB order instead of sorted by `emp_code` ascending. | Non-deterministic order violating OpenAPI contract specification. | Added `.sort("emp_code", 1)` to cursor query. |
| 9 | `punch_in` (lines 101–113) | Unhandled missing employee. If `emp_code` does not exist, `emp` is None; line 113 `emp["shift_start"]` raises an unhandled `TypeError` (500 Internal Server Error). | Punching in for a non-existent employee `EMP9999` crashes with 500 instead of returning 404. | Added explicit check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 10 | `punch_in` (lines 104–105) | Check-then-insert race condition on duplicate punch-in. Two concurrent requests both pass `find_one()` and create duplicate daily records. | Sending parallel punch-in requests for same employee and date yields two 201 responses. | Created compound unique index on `(emp_code, date)` at startup and caught `DuplicateKeyError` to return 409. |
| 11 | `punch_in` (line 109) | Accepts any arbitrary status string including `ABSENT` or `LEAVE`, violating OpenAPI contract. | Calling `POST /attendance/punch-in` with `{"status": "LEAVE"}` returns 201 instead of 422. | Restricted status to `Literal["PRESENT", "WFH", "ON_DUTY"]` via Pydantic model with 422 validation. |
| 12 | `punch_in` (line 103) | Attendance date calculation uses naive local date and fails to account for overnight shifts. | Punching in at 05:30 IST for an overnight shift 22:00–06:00 assigns today's date instead of yesterday's start date (R1). | Implemented `compute_attendance_date` with overnight shift boundary resolution. |
| 13 | `punch_in` (lines 119–120) | Injects `doc["id"] = str(res.inserted_id)`. The OpenAPI `AttendanceRecord` schema has no `id` property. | Schema validation failure against `openapi.yaml`. | Removed `id` field from response transformation. |
| 14 | `list_attendance` (lines 144–147) | Catastrophic memory exhaustion: `docs = list(db.attendance_logs.find(q))` loads all records into Python memory for sorting and slicing. | On a dataset of ~100,000 records, the endpoint causes high RAM consumption and latency spikes. | Pushed sorting and pagination directly into MongoDB engine with `.sort(...).skip(...).limit(...)`. |
| 15 | `list_attendance` (lines 136–141) | Missing validation for `date_from > date_to`. | Passing `date_from=2026-07-10&date_to=2026-07-01` returns 200 `[]` instead of 422. | Added check: `if date_from > date_to: raise HTTPException(422, ...)`. |
| 16 | `health` probe (lines 72–74) | Returns static `{"status": "ok"}` without checking MongoDB connectivity. | Stopping MongoDB or providing an invalid URI still returns 200 instead of 503. | Added `db.command("ping")`, raising 503 on database disconnection. |

### Things examined and confirmed NOT to be defects
1. **IST Timezone Definition (`IST = timezone(timedelta(hours=5, minutes=30))`):**
   - Correctly defines Indian Standard Time as required by Rule R1 for shift hours and calendar day demarcation.
2. **Synchronous Route Handlers with PyMongo:**
   - Defining route functions with `def` allows FastAPI to execute them within Starlette's threadpool workers (`run_in_threadpool`). This prevents event loop blocking while maintaining clean compatibility with PyMongo operations and explain command execution.
